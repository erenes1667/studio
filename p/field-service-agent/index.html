    04 / SAFETY RULESPlain code decides. The model writes.

    The model never gets the last word on anything that can hurt a customer, a technician or the shop. These rules are plain code, not model output, and sit in server.py and agents.py.

    Emergency keywords force the emergency path

    Gas smell, flooding, burst pipe, no heat, sewage, carbon monoxide, sparks, fire. Urgency becomes emergency, the emergency line is added, and a gas smell adds "leave the building and call 911". Emergency jobs go to on-call technicians only.

    The model never quotes a price

    Any dollar figure in a model text is replaced by a fixed line. A price question gets the fixed line too. It covers customer texts, technician texts, order notes and the report.

    The roster check is code

    The model ranks technicians. Code then checks zone, skill, slot and on-call status and drops anyone who fails. Nobody off the roster is ever texted.

    Only an explicit YES assigns a job

    Accept and decline words come from templates.json. Free text such as "not free until 3pm" can only decline or ask again. It can never assign.

    Report numbers come from a count

    Code counts the orders. If the model writes a number it was not given, the report falls back to the counted summary.

    Unknown zone means a person looks

    If no service zone is found in the address, nothing is dispatched. The job goes to the office. A cap of 300 model calls per process stops a runaway loop.

    Try the rules

    Runs the same patterns as server.py in your browser. No model, no network.

    05 / HANDOVER DOC (SAMPLE)You can run it without me

    The gig asks for a solution you can manage yourself. This is the one-page doc that ships with it, written for this sample shop.

    Field service agent: handover

    Sample shop. Fictional data. Read by the agents on every run.

    1. What runs, in order

    Missed call, then text-back, then the intake agent books a slot. The dispatcher matches a technician and texts the offer. A YES makes the order row. The report agent writes the morning report.

    2. Change the roster

    Open roster.json. One block per technician. Save the file. The next run reads it. No restart.

    {"id": "t-new", "name": "First Last",
 "phone": "<technician mobile>",
 "zones": ["Tempe", "Mesa"],
 "skills": ["leak", "drain"],
 "off_slots": ["wed-am"],
 "on_call": false}
    • zones: only these cities get texted for a job.
    • skills: keys from the skills list at the bottom of the file.
    • off_slots: slot ids the person cannot take.
    • on_call: true means they take emergencies.

    3. Change hours and slots

    Open business.json. hours is the text the intake agent tells customers. office_opens sets when the morning report is ready. Each entry in slots is one bookable window: an id, a label and a day.

    4. Change templates

    Open templates.json. Keep the {placeholders} as they are.

    KeyWhat it changes
    customer_openingThe first text after a missed call
    dispatch_styleHow the model words the technician text
    dispatch_tailThe YES or NO line added to every offer
    customer_confirmThe text when a technician accepts
    accept_words, decline_wordsWords that count as YES or NO
    no_price_lineThe fixed line used instead of any price

    5. What to leave to a developer

    Emergency keywords and the price filter live in server.py. The roster check and reply parser live in agents.py. Adding a keyword is one line.

    6. When something looks wrong

    Every run saves each step: input, raw model text, the result after the checks, and a guards list. Read guards first. It says what the code changed or dropped.

    The doc is the contract for handover: it names the files you edit and the files you leave alone. It names no real client, number or company.
