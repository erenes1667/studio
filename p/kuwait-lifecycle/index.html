How Meta approval shapes the plan

  1. Template first. Business-initiated messages outside the 24-hour customer window need an approved template.
  2. Category at submission. Utility or marketing is set when the template is submitted. Meta can reclassify it, and the provider shows the final category.
  3. Opt-in before send. A profile with no WhatsApp opt-in never receives a template.
  4. Two languages. English and Arabic are submitted as separate versions. The Arabic text comes from the client or a native translator.
  5. Submitted early. Templates go in on day 2 of the plan, so review time never blocks the build.

  1. Shopify events reach Klaviyo through the Shopify integration. Order history and browsing build the segments.
  2. A Klaviyo flow action calls an n8n webhook with the profile id, the step name and the template variables.
  3. n8n re-checks consent, picks the approved template and calls the provider API.
  4. The provider sends through the WhatsApp Cloud API. Status and replies come back the same way.
Return pathProvider status webhooks go to n8n. n8n writes them to the Klaviyo profile as events: delivered, read, replied, STOP. STOP flips wa_opt_in to false at once. These events also power the 'clicked since day 0' split.

05 / QA plan

Nothing goes live unchecked.

Three passes: staging, one live test per flow, and a tag check on every step. The checklist below is the live version of the third pass.

Pass 1

Staging

  • Shopify development store and a separate Klaviyo test list.
  • Flows built in draft. Waits cut to minutes.
  • n8n test workflow points at the provider sandbox or a test number.
  • Every wait restored to its real length, then checked off.
Pass 2

One live test per flow

  • One seed profile per flow on the real store.
  • Check the entry trigger, the first message and the exit.
  • Long waits (90 days, product cycle) are proven in staging.
  • Send windows checked against Kuwait time, Sunday to Thursday.
Pass 3

Tag check per step

  • Each step writes one named tag.
  • After each test run, open the profile and tick the tag.
  • A missing tag means the step did not run. That is a fail.
  • Results go into the handover doc.
